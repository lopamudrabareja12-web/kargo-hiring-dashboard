Hiring Dashboard Components Map

How one CV moves from Arjun's upload to a sent email. Personal details split off at the start and never reach the AI. Nothing is sent until Arjun confirms.

The flow, step by step

  1. Arjun uploads a CV and picks the role applied for.
  2. The file and the role enter the system.
  3. Code parses the text and separates name, email and phone from the CV content.
  4. Personal details go to a private table. The rubric (built beforehand from the 8 hire profiles) sits in the database.
  5. Gemini sees only the redacted content and the rubric. It rates every criterion for both PM and SPM, with a one-line reason each.
  6. Code does the maths: weighted totals, ranking per role, and the line (top 5 per role).
  7. Gemini writes a 3-sentence brief for the top 5 and a draft email for everyone, with [NAME] as a placeholder.
  8. Scores, briefs and drafts are saved.
  9. Arjun reads the ranked dashboard and confirms each email. This is the human gate.
  10. On confirm, code swaps in the real name, Resend sends it, and the record is marked sent.

The Cut

Asked for: emails to selected and rejected candidates going out without Arjun managing them.

Killed by Check 06 and Check 09: a wrongly rejected candidate never comes back, so the mistake is invisible, and a rejection nobody signed off has no one accountable for it.

Built instead: the system drafts every email; Arjun confirms each one. It ranks and explains. It never rejects on his behalf.

What changed from the class map

  • A Database lane, so the private personal-details table and the rubric are visible.
  • Scoring split in two: AI rates the evidence, code adds it up. Scores stay reproducible and explainable.
  • Top-5 line and [NAME] swap shown explicitly.
  • Confirm drawn as its own gate before anything reaches Resend.
